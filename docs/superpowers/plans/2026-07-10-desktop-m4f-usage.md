# Windows/Linux Desktop Client — Milestone 4f (Usage Panel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Usage panel overlay: per-provider cards (Claude / Codex / Cursor) showing rate-limit windows with progress bars + reset times, Claude's per-model weekly caps (Sonnet/Fable) + extra-usage credits, and Codex's banked rate-limit-reset redemption. Ports `apps/android/.../settings/MoreScreens.kt`'s `UsageScreen` + the provider cards — but consumes the **typed** `BrokerApi.usage()` (`UsageResponse`) instead of Android's `usageRaw()` + org.json `parseUsage` path.

**Architecture:** A `UsageScreen` full-pane overlay (the third overlay, exactly like the launcher + archived overlays: a `Box` drawn last over the still-mounted workspace, reached from a File ▸ "Usage…" menu item + the SessionDetail overflow ⋮ row). On open it loads `app.usage()` once (point-in-time snapshot, re-fetched each open). Three provider cards render from the typed `UsageResponse` (`claude`/`codex`/`cursor`/`errors`); the Codex card's "redeem banked reset" button calls `app.redeemCodexReset()` and updates the card in place from the returned refreshed `CodexUsage`. Skips Android's `org.json` parsing entirely — the shared `jvm()` brain already deserializes `UsageResponse` via kotlinx.serialization.

**Tech Stack:** Compose Desktop (`LinearProgressIndicator` for window bars, a card composable), shared `BrokerApi.usage()` → `UsageResponse{claude,codex,cursor,opencode,errors}` + `redeemCodexReset()` → `CodexResetResult`, shared window types (`ClaudeWindow`/`CodexWindow`/`CursorUsage`/`ClaudeExtraUsage`/`CodexCredits`), `kotlinx-datetime` for reset formatting (already a shared dep).

## Ground rules

All prior-milestone rules hold (standard gradle invocation with /home/ahmet/.cache logs + TMPDIR; Xvfb :77 + `SKIKO_RENDER_API=SOFTWARE`; paired config; xwd+Pillow; NO xdotool — env hooks; never restart the broker; snake_case tests; commit trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`; touch ONLY apps/desktop/src, NEVER build). Suite baseline at M4f start: desktop 394 / shared jvmTest 292 / android compile green.

- `runApi` for the new broker calls. `usage()` → `UsageResponse?` (degrade to `null` on failure → the screen shows "Unable to load usage data."). `redeemCodexReset()` → `CodexResetResult?`.
- **Use the TYPED path.** `BrokerApi.usage()` returns a deserialized `UsageResponse`; do NOT port Android's `usageRaw()` + `parseUsage(JSONObject)` — the desktop has no org.json dep and shouldn't add one. The typed model (BrokerApi.kt:206-281) has every field Android's private data classes have.
- **`resetsAt` type differs per provider** (the load-bearing correctness bit, called out in BrokerApi.kt:204-205): Claude's `ClaudeWindow.resetsAt` is an **ISO-8601 String**; Codex's `CodexWindow.resetsAt` is a **Double of epoch SECONDS**; Cursor's `billingCycleEnd` is an **ISO-8601 String**. The reset-formatter must take the already-typed value per provider — do NOT stringify-then-reparse Android-style. Port Android's `formatReset` semantics (`resets in Xh Ym` when <24h, else `resets <Mon D>`, `resets soon` when ≤0) but as two typed entry points (ISO string, epoch-seconds Double).
- Codex reset banking: the button is shown when `codex.resetCredits > 0` (banked resets available). `redeemCodexReset()` returns `CodexResetResult{code, windowsReset, codex}` — `code ∈ reset | nothing_to_reset | no_credit | already_redeemed`; on `code == "reset"` with a non-null `codex`, replace the card's codex state in place. Surface the other codes as a transient inline line (no snackbar host — the recurring M4-polish gap; document it).
- `opencode` usage exists in the model but Android's UsageScreen renders only Claude/Codex/Cursor — match Android (omit the opencode card; it's not in the parity surface). Don't add a card the reference UI doesn't have.
- Per-provider `errors: Map<String,String>`: a provider present in `errors` renders its card in an error state (Android passes `u?.errors?.get("claude")` into each card). Port that — a provider that failed to load shows its error text, not a blank card.
