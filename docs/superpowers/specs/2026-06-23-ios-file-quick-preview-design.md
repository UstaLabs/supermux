# iOS File Quick Preview — Design (2026-06-23)

## Goal

Tapping a **non-photo attachment** in the iOS app should open a native **Quick Look**
preview, the same previewer photos already use — instead of jumping straight to the iOS
share sheet. Share stays reachable (Quick Look's toolbar has a share button); it just stops
being the *only* thing that happens. Scope (confirmed with user): **all** non-photo
attachments — documents, video, audio, and voice notes.

## Context (current behavior)

`apps/iosApp/Supermux/Chat/ChatMessages.swift` renders each attachment via `AttachmentView`,
which splits on `isImage` (`mime` starts with `image` or `kind == "photo"`):

- **Images** (`imageView`, L57-74): rendered inline; tapping writes the bytes to a temp file
  and presents `.quickLookPreview($previewURL)` — native Quick Look.
- **Everything else** (`fileRow`, L83-118): a file chip. Tap downloads via
  `broker.downloadFile(_:name:onProgress:)` (streaming, with a progress bar), then on
  completion sets `showShare = true`, which presents `ShareSheet` — a thin
  `UIActivityViewController` wrapper (L152-158). A second tap re-opens the share sheet.

So non-photo files never get a preview; they go download → share sheet. The user's report is
accurate.

`Attachment` (shared KMP model, `apps/shared/.../proto/Frames.kt`) carries: `file_id`,
`kind`, `mime`, `size`, `name`. There is a real XCTest target at `apps/iosApp/SupermuxTests/`
and the project is generated by XcodeGen from `apps/iosApp/project.yml`.

## Decisions (and why)

- **Unified Quick Look for non-photo files** (over custom per-type viewers, and over keeping
  share-as-default with a separate preview gesture). `fileRow`'s tap routes to the same
  `previewURL` + `.quickLookPreview` path the image branch already uses. Quick Look natively
  previews PDF, text/CSV, Office/iWork, video, audio, and zip contents, and for types it
  can't render it shows a generic file with a share button — so it degrades gracefully and is
  far less surface area than hand-rolled viewers. Custom viewers (PDFKit, text views, …) were
  rejected as redundant; a separate "preview" gesture was rejected because preview should be
  the *default* tap, which is what the user asked for.
- **Preview is the default tap; share moves into Quick Look's toolbar.** No separate
  long-press→share gesture (YAGNI) — Quick Look's built-in share (↑) button drives the same
  system activity sheet.
- **Download to a Quick Look-friendly filename.** Quick Look identifies a file by its
  extension/UTI. Today the file is downloaded under `att.name ?? "file"`, which loses the type
  when `name` is missing or extension-less. We introduce a pure helper
  `previewFilename(name:mime:)` that keeps `name` when it already has an extension, otherwise
  appends an extension derived from `mime` (prefer `UTType(mimeType:)?.preferredFilenameExtension`,
  e.g. `text/plain → txt`; fall back to the mime subtype; fall back to a bare base name). This
  generalizes the existing image-only `imageFileName` getter, which is refactored to use it.
- **Reuse the existing `previewURL` state.** `imageView` and `fileRow` are mutually exclusive
  (only one is ever in the view tree), so both branches can drive the single
  `@State previewURL` and one `.quickLookPreview` binding.
- **Remove the now-dead share path.** Once `fileRow` previews instead of sharing, `showShare`,
  the `.sheet`, and the `ShareSheet` struct are unused. They are removed, and the stale comment
  in `ChatView.swift:261` ("photos use system Quick Look") is updated to reflect that all
  attachments now use Quick Look.
- **Downloaded-state icon** changes from `square.and.arrow.up` (share) to an `eye`/preview
  glyph, since the action is now "preview," not "share."
- **iOS only.** Android already opens files via `Intent.ACTION_VIEW` (open-in-viewer, falling
  back to share), so it is already close to this behavior; out of scope unless parity work is
  requested separately.

## Components & flow

`AttachmentView.fileRow` (the only changed view):

1. **Tap, not yet downloaded** → `startDownload()` streams the file to disk under
   `previewFilename(name: att.name, mime: att.mime)` with the existing progress bar.
2. **Download completes** → set `fileURL` and `previewURL = fileURL` → `.quickLookPreview`
   presents Quick Look.
3. **Tap, already downloaded** → set `previewURL = fileURL` → Quick Look opens instantly (no
   re-download; `fileURL` is retained).
4. **Inside Quick Look** → user can share via the toolbar's share button (system flow).

`previewFilename(name:mime:)` — pure, free function (testable):
- `name` has an extension → return `name` unchanged.
- else `"\(base).\(ext)"` where `base = name (non-empty) ?? "file"` and
  `ext = UTType(mimeType: mime)?.preferredFilenameExtension ?? mime.subtype`.
- `mime` nil/unresolvable → return bare `base`.

## Error handling

- **Download failure** → unchanged: `failed = true`, chip shows "Download failed — tap to
  retry," tapping retries.
- **Type Quick Look can't render** (e.g. opus/ogg voice notes) → Quick Look shows its generic
  preview with a share button. Acceptable graceful fallback. (Inline voice playback, if ever
  wanted, is a separate feature.)
- **Missing/extension-less `name`** → handled by `previewFilename` so Quick Look can still
  identify the file by mime-derived extension.

## Testing

- **Unit (TDD):** `previewFilename(name:mime:)` in `SupermuxTests/` — cases: name with
  extension is kept; extension-less name + `application/pdf` → `<name>.pdf`; nil name +
  `application/pdf` → `file.pdf`; `text/plain` → `.txt` (proving subtype-split alone is
  insufficient — "plain" is wrong); nil name + nil mime → `file`.
- **Build:** XcodeGen generate + `xcodebuild` build of `iosApp` and run `SupermuxTests`
  (remote-Mac simulator over SSH, or xtool on Linux).
- **Manual:** on a build, tap a PDF, a `.txt`, an `.mp4`, and an `.m4a` voice note → each
  opens in Quick Look; the in-preview share button works; a second tap does not re-download.
  SwiftUI view wiring has no unit-test harness, so this step is manual/simulator.

## Out of scope

- Android parity (already opens via `ACTION_VIEW`).
- A separate long-press→share gesture (Quick Look's toolbar share covers it).
- Inline audio/voice playback.
