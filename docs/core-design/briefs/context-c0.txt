WHAT TO PROVE (per agent: claude, codex, cursor, grok, opencode)
Each item gets its own distinct code word.

At startup:
 1. Instructions: append-only per-session channel, never written into the workdir.
    claude: --append-system-prompt-file. codex: app-server thread/start `developerInstructions`
    (schema: `codex app-server generate-json-schema --out <dir>`). grok: `--rules` while
    running as `grok agent stdio` (the way the core launches it; see src/agents/index.ts).
    cursor: look for ANY per-session channel that isn't the repo: a rule in the session HOME, a
    user-rules file, ACP _meta, a flag, an env var. Report what you tried. opencode: config
    `instructions`.
 2. Skills given as a folder of <name>/SKILL.md (a skill whose body says the code word; prompt the
    agent to use that skill by name). claude: wrapped in a generated plugin dir and passed with
    --plugin-dir. codex: app-server `skills/extraRoots/set`, and separately <CODEX_HOME>/skills.
    cursor: generated plugin dir with --plugin-dir. grok: config [skills] paths.
    opencode: skills.paths.
 3. Plugins: one plugin folder carrying .claude-plugin/.codex-plugin/.cursor-plugin manifests plus
    skills/. claude/cursor: --plugin-dir. claude: also `--plugin-dir <folder of plugins>` loading
    each child. codex: install into the session CODEX_HOME (marketplace name == manifest name
    rule; see src/core/plugins/adapters/codex.ts). grok: `grok plugin install` with HOME = session
    home. opencode: the mapped parts.
 4. MCP: a stdio MCP server built on @modelcontextprotocol/server v2 (install it in the scratch dir,
    NOT in package.json). It logs the `initialize` request, so record the protocolVersion and
    clientInfo each CLI sends, and whether the v2 server negotiates successfully. A tool returns
    the code word. Also: does each CLI pass that MCP server to a subagent it spawns? Try once,
    cheaply.

In flight (same live process, same conversation; record "live", "needs reload", or "impossible"):
 5. Tools list_changed: the probe server registers a new tool mid-session and sends
    notifications/tools/list_changed; can the agent call the new tool on the next turn?
 6. Add a skill and a plugin mid-session. claude: add a symlink to the --plugin-dir folder of
    plugins, then the stream-json control requests `reload_plugins` / `reload_skills` (find their
    exact request shape in the claude binary strings or the Agent SDK). codex:
    skills/extraRoots/set, plugin/install. grok: rewrite [skills] paths. Do NEW entries appear,
    not just edited ones?
 7. Add an MCP server mid-session. claude: `mcp_set_servers`. codex: config/value/write +
    config/mcpServer/reload (or the thread `config` override). ACP agents: a new process
    `session/load` with the new mcpServers. Does the conversation survive (the agent recalls an
    earlier code word)?
 8. Change instructions mid-session. claude: `apply_flag_settings`: is there an
    appendSystemPrompt-like key? codex: thread/resume with new developerInstructions on the same
    process: does it replace or add to the original? Others: reload.
 9. Reload fallback: for the ACP agents, a session/load in a new process with changed config
    keeps the conversation (it recalls an earlier word). The core's account-switch path already
    does this for claude and codex, so don't redo those.
